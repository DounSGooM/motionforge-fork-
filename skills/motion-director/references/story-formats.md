# Story formats

A format is the skeleton of the video: what pulls the viewer from one beat to the next. Choose it before writing the script. Percentages are shares of the total runtime; adjust to the voice.

## Pick by the content

| The content is… | Format |
|---|---|
| a result that looks hard to believe | 1 Proof first |
| a pain the viewer has right now | 2 Problem → fix |
| several tools, tips or examples | 3 Countdown list |
| a popular belief that is wrong or incomplete | 4 Myth check |
| a visible change (design, code, room, number) | 5 Before / after |
| a procedure the viewer will repeat | 6 Walkthrough |
| a development over time | 7 Timeline |
| one person, product or object with a goal | 8 Micro-story |

When two fit, prefer the one whose first frame is easier to make striking.

---

## 1. Proof first
- **Engine:** show the finished result, then reveal how it was made.
- **Beats:** result + claim (0–10%) → "here is how" turn (10–15%) → 2–4 making-of steps (15–80%) → result again with one new detail (80–92%) → CTA (92–100%).
- **Constant:** the result itself; it returns at the end, changed or annotated.
- **Transitions:** hard cuts on sentence ends; a rewind or wipe at the turn.
- **Pitfall:** the proof must be real footage or real output. A mock result kills the format.

## 2. Problem → fix
- **Engine:** name a pain precisely, show why it happens, then the fix.
- **Beats:** the pain in one concrete image (0–12%) → the cause (12–30%) → the fix in 1–3 moves (30–80%) → the fixed state (80–92%) → CTA.
- **Constant:** the same object or screen, broken then working.
- **Transitions:** the broken element is the bridge (a red error turns green, a jammed bar fills).
- **Pitfall:** a vague pain ("growth is hard") gives a vague video. One situation, one fix.

## 3. Countdown list
- **Engine:** a promised number of items, delivered one per beat.
- **Beats:** the number + payoff promise (0–8%) → items, equal rhythm, 3–6 s each (8–88%) → the strongest item last or a quick recap grid (88–95%) → CTA (save-worthy).
- **Constant:** a counter or index tag in the same screen position ("3/7").
- **Transitions:** cuts on the beat or on each item's name; the counter ticks on the cut.
- **Pitfall:** items that look alike. Give each item its own layout or real logo/screen.

## 4. Myth check
- **Engine:** state a belief the viewer holds, test it, replace it.
- **Beats:** the belief, said plainly (0–10%) → evidence against it (10–45%) → what works instead (45–85%) → one-line rule to remember (85–95%) → CTA (comment prompt works well).
- **Constant:** the belief as a text object that gets crossed out, split or rewritten.
- **Transitions:** strike-through, split screen, flip.
- **Pitfall:** the evidence must be sourced (claim list). No straw men.

## 5. Before / after
- **Engine:** one frame, two states, and the process between them.
- **Beats:** after (flash-forward, 0–6%) → before (6–15%) → the changes in order (15–85%) → after, held, with a comparison wipe (85–95%) → CTA.
- **Constant:** a locked framing; only layers change.
- **Transitions:** wipes and dissolves on the same framing; no camera moves between states.
- **Pitfall:** the "before" made artificially bad. Use the real before.

## 6. Walkthrough
- **Engine:** steps the viewer will repeat, each with a visible outcome.
- **Beats:** what you will be able to do (0–10%) → step 1..n, one screen and one outcome per step (10–85%) → the finished outcome (85–93%) → CTA ("save this for later").
- **Constant:** a step indicator and the same device frame (browser, phone, terminal).
- **Transitions:** zoom into the exact UI element being used; cursor or tap marks.
- **Pitfall:** more than 5 steps in 60 s. Merge steps or split into a series.

## 7. Timeline
- **Engine:** real chronological order with a visible clock (year, version, day).
- **Beats:** today's state as the hook (0–8%) → origin (8–20%) → milestones, faster as they get recent (20–80%) → today again, now understood (80–92%) → what is next or CTA.
- **Constant:** the date counter and one object that evolves (a device, a logo, a line).
- **Transitions:** morph the evolving object from one era to the next; avoid plain cuts.
- **Pitfall:** every date is a claim. Source each one or drop it.

## 8. Micro-story
- **Engine:** someone or something wants a thing, hits an obstacle, changes, gets a result.
- **Beats:** the want (0–15%) → obstacle (15–35%) → attempt and turn (35–70%) → result (70–90%) → the takeaway in one line + CTA.
- **Constant:** the protagonist, same color and silhouette in every scene.
- **Transitions:** match cuts on the protagonist's position; a short silence before the turn.
- **Pitfall:** invented testimonials. A story about a real customer needs the user's confirmation; otherwise label it as an illustration.

---

## Rules for every format
1. The hook keeps its promise inside the video.
2. Something new reaches the screen every 2–4 seconds.
3. One reserved accent color means one thing for the whole video.
4. A short drop in sound and motion (0.3–0.8 s) before the biggest reveal; the strongest hit lands on the reveal.
5. The last frame holds at least 1 s and closes the idea (result, rule or CTA), not a logo alone.
6. The ending echoes the opening image.
